# MewCode v0.1 Spec

## 背景

MewCode 是一个从零开始构建的命令行 AI 助手，定位类似 Claude Code 的终端对话工具。本阶段只实现最小可用的纯对话能力：用户在终端启动 MewCode 后进入交互式界面，输入自然语言问题，MewCode 调用配置中的大模型服务，并把模型回复以流式方式逐字显示在终端中。

当前阶段的重点是打通“终端交互、多轮上下文、可切换模型供应商、流式输出”这条主路径。工具调用、文件读写、代码编辑、项目理解等 Coding Agent 能力暂不进入本阶段范围。

## 目标

- 提供一个可以从终端启动的 MewCode 交互式对话界面。
- 支持用户连续输入多轮问题，并让模型回复能够基于前文上下文生成。
- 支持通过 YAML 配置文件切换 Anthropic Claude 和 OpenAI 两类模型后端。
- 支持模型回复流式输出，用户不需要等待完整回复生成完才能看到内容。
- 支持 Claude 的 extended thinking 配置开关。
- 建立统一的 Provider 抽象，为后续增加新模型后端保留扩展点。
- 明确本阶段不实现 tool use、文件操作、代码编辑等 agent 功能。

## 功能需求

- F1: 用户可以在终端中启动 MewCode，并进入持续运行的交互式对话界面。
- F2: 交互式界面应显示清晰的输入提示，让用户可以输入自然语言问题并提交。
- F3: 用户每次提交问题后，MewCode 应调用当前配置的大模型后端生成回复。
- F4: 模型回复必须以流式方式显示，用户应能在回复生成过程中逐步看到新增文本，而不是等待完整回复一次性返回。
- F5: MewCode 应保存当前进程内的多轮对话历史，并在后续请求中把必要的上下文发送给模型，使模型能够基于前文继续回答。
- F6: MewCode 应通过 YAML 配置文件读取供应商信息；每个供应商配置包含 `name`、`protocol`、`model`、`base_url`、`api_key`、`thinking` 六个字段，其中 `thinking` 为可选字段。
- F7: 用户应能通过配置选择 Anthropic Claude 后端或 OpenAI 后端；不同后端在对话层表现为同一种“发送消息并流式接收回复”的能力。
- F8: 当选择 Anthropic Claude 且配置启用 `thinking` 时，MewCode 应请求模型启用 extended thinking，并能处理模型返回的思考相关流式内容。
- F9: 当配置缺失、格式错误、协议不支持或认证信息缺失时，MewCode 应给出清晰错误信息并退出或阻止继续发送请求。
- F10: 当前阶段不得向模型提供 tool use 能力，也不得执行文件操作、代码编辑、shell 命令或项目分析行为。
